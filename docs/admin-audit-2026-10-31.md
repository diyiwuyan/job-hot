# JOBHOT 后台与产品检查（2026-10-31）

## 已确认的问题与改动

| 优先级 | 问题 | 证据 | 本轮处理 |
| --- | --- | --- | --- |
| P0 | 注册用户统计少报 | 旧统计从 `page_views.user_id` 去重；未访问的注册用户不计入，且 API 查询最多返回默认页数 | 改用 `admin_list_users_safe()` 的注册用户列表；活跃用户从该 RPC 的最后访问时间计算 |
| P0 | 访问趋势可能在 9 月 11 日部署后中断 | 9 月 11 日写入新增城市字段，并在 `insert()` 后要求返回 ID；访客无 `SELECT` 权限时写入会失败，Supabase 的 `{error}` 又未检查 | 改为专用写入/时长 RPC；迁移前回退为无需返回行的插入；展示统计错误与最近记录日 |
| P0 | 旧 `admin_list_users()` 泄露用户档案 | `security definer` 函数直接读取 `auth.users`，函数内无权限检查，而 PostgreSQL 默认给 PUBLIC 执行权 | 迁移撤销直接执行权，保留带管理员校验的安全入口 |
| P1 | 添加账号会影响当前登录态 | 管理页直接在超级管理员浏览器调用 `auth.signUp()` | 用不持久化登录态的独立客户端注册；明确提示用户需要邮箱验证 |
| P1 | 旧管理员管理页可能操作错误用户 | 用当前管理员 ID 填充目标管理员 ID | 旧地址跳转至统一账号管理页，角色操作只走 `admin_set_role` |
| P1 | 旧访问时长更新策略过宽 | 旧 SQL 中 `session_id = session_id` 永真 | 迁移删除旧策略，通过 session 与页面 ID 同时校验更新 |
| P2 | 趋势把最后一天当今天 | 首页卡片直接取 `dailyStats[0]`，即使该日是 9 月 10 日 | 只认北京时间当天；无数据时显示 0/— 与停更提示 |
| P2 | 岗位数据失败被显示成“无岗位” | 请求异常时设置空列表 | 区分网络/数据错误与真正无结果，提供重试 |
| P2 | 搜索结果显示伪 0 分 | 搜索索引将 `score` 初始化为 0 | 无评分时隐藏分数；导出按钮明确只导出当前页 |

生产库预检查确认 `page_views` 缺少全部 3 个城市字段；9 月 11 日的代码变更与停更时间吻合。前端修复上线后，现网已出现 2026-10-31 的新访问记录，说明写入链路已恢复。旧代码的 `INSERT ... RETURNING` 在访客 RLS 下也有失败风险。修复不会补回历史缺失的访问数据。

2026-10-31 已在生产 Supabase SQL Editor 执行本迁移，并补建原先缺失的 `admin_city_stats(integer)`。执行后验证：城市字段 3 个；旧 `admin_list_users()` 对 `anon`/`authenticated` 均不可执行；匿名访问写入与时长 RPC 可执行；旧宽松更新策略已删除；`auth.users` 共 8 人。

## 生产环境落地顺序

1. 数据库迁移已执行，关键权限与列已复核。
2. 前端发布后分别用匿名、普通用户、超级管理员访问页面；检查当日 `page_views` 增长、后台总用户数与账号列表一致。添加账号仍遵循公开注册的邮箱确认规则；不要用真实用户做测试账号。
3. 如需对 9 月 10 日后的每一条失败请求做归因，可继续查询 Supabase 历史日志；缺失的历史访问量无法还原。

Supabase 控制台由用户登录后完成迁移；服务角色密钥没有进入前端或仓库。

## 用户与产品视角：下一批优先事项

| 顺序 | 用户遇到的阻碍 | 建议 |
| --- | --- | --- |
| 1 | 首页岗位很多，但不清楚从哪里开始 | 在筛选区增加“应届/实习/已收藏”快捷入口；首次访问提示如何按城市、专业缩小范围 |
| 2 | 岗位可信度、时效难判断 | 每条岗位展示采集时间、原始来源和截止日期状态；过期岗位默认折叠；提供“链接失效”反馈 |
| 3 | 收藏与每日推荐之间缺少连续流程 | 工作台展示“待投递→已投递→笔试→面试”状态，并允许从收藏一键加入进度 |
| 4 | 不同栏目入口多，名称相近 | 保持“招聘信息→求职测评→资料中心→我的求职工作台”四个主要任务入口；移动端优先展示搜索、筛选与收藏 |
| 5 | 后台故障常在数周后才被发现 | 增加最近写入时间和每日低流量告警；将采集量与页面浏览量分开监控 |

该检查覆盖仓库中统计、账号管理、访问记录、岗位首页的静态代码与本地构建；不等同于对生产数据库、网络配置或第三方服务的完整渗透测试。
